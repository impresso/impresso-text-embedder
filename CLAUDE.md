# impresso-text-embedder

Multilingual text embeddings for the [Impresso](https://impresso-project.ch) project: yearly `.jsonl.bz2` shards on S3, embedded with [`Alibaba-NLP/gte-multilingual-base`](https://huggingface.co/Alibaba-NLP/gte-multilingual-base) via `sentence-transformers`, written back one-output-per-input.

This file is the **rulebook for Claude sessions** — locked decisions, the data contract, gotchas. **If something here is wrong or out of date, fix it here first** — every session loads this file.

## Branch goal — chunking-strategy evaluation

Current branch: `research/chunking-eval`. The production package landed (history in [`.history/plan.md`](./.history/plan.md)); this branch is a **side-research project** that does not change production behaviour until findings land.

**Research question.** Production currently chunks only when `tokens(doc) > model_max_tokens` (`gte-multilingual-base`'s 8192). The argument was theoretical: CLS-pooling means chunk-and-pool drops cross-chunk attention without a recovery mechanism. The question this branch answers empirically: **on Impresso historical newspapers, does forcing sub-8k chunking + mean+L2 pool produce better doc-level embeddings than one-shot encode at 8190?**

**Scope (locked with the user):**

- **Embedding level**: `--embedding-level text` only (one vector per doc, mean+L2 when chunked). Chunk-level retrieval is a different question and is out of scope.
- **Languages**: fr / de / lb. Italian deferred — chars-per-token differs across Romance / Germanic / Luxembourgish, so per-language sweeps matter.
- **Strategies**: 16 scenarios in `research/scenarios.py` — `truncate` baseline (S0); `fixed-window` (S1–S5), `token-budget` (S6–S10), and `semantic` chonkie (S11–S15) each covering the same five chunk sizes {512, 1024, 2048, 4096, 8190}. The grid is intentionally symmetric so cross-family comparisons at a fixed size are first-class. Sliding-window with overlap is out — would need a new `stride` kwarg on `FixedWindowStrategy` we are not adding on this branch.
- **Aggregation**: `mean` for the primary sweep. Length-weighted / max / first-chunk ablations only on the winning chunker.
- **Corpus**: long articles (>4000 raw tokens), high OCR quality, topic-bounded slice only as far as needed to keep generation cost bounded.
- **Relevance signal**: Chroma-style synthetic LLM query+excerpt pairs (token-level Recall@k, Precision_Ω, IoU on chunk-vs-excerpt overlap). Impresso's native annotations (topic clusters, text-reuse, NER) are explicitly **not** used — keeps methodology comparable to the published chunking-eval literature.
- **Cross-lingual ablation** (optional): fr-language queries against de/lb pools of the same window. Gated on the monolingual sweep producing a clear winner.

**Deliverables:**

- A reusable eval harness, kept off the production hot path under `src/impresso_text_embedder/research/` (resolved in step 1; the sweep CLI `research/embed_sweep.py` + scenario registry `research/scenarios.py` shipped in step 3).
- A recommendation on the default `--long-doc-strategy` and `--long-doc-chunk-tokens` (or evidence that the current 8190-no-chunk default holds), per language
- Per-language `chars_per_token` calibration

**Out of scope on this branch:**

- Chunk-level retrieval (`--embedding-level chunk`) — different question, different metrics.
- Late chunking (Jina 2024) — rejected by the inherited decision (assumes a mean-pooled model; would need retraining for our CLS-pooled embedder). Reconsider only if we switch embedders.
- Production-pipeline changes, until findings justify a default change.
- New CLI flags or schema fields (the existing `--long-doc-*` flags + the chunking/aggregation registries are sufficient).

Live ledger for this branch: [`.progress/plan.md`](./.progress/plan.md). Per-experiment notes land at `.progress/<slug>/notes.md`.

## Hardware target

A100 + H100 (incl H200), **one GPU per container**, same image. `accel.py` auto-detects the arch at startup and picks the per-profile default batch size; xformers' `memory_efficient_attention` dispatches FA2/FA3 transparently from inside the bf16 autocast region. Model weights stay fp32; bf16 lives only inside the autocast scope. Horizontal throughput scales by submitting **N independent runai jobs** with disjoint file shards (`--shard-index i --num-shards N`) — *not* by binding multiple GPUs into a single container. Multi-node, DDP, FSDP, tensor-parallel, V100, Blackwell are out of scope (see [Non-goals](#non-goals)). Detail in `.history/gpu-profiles/notes.md`, `.history/gpu-throughput/notes.md`, and `.history/multi-gpu-sharding/notes.md`.

For research on this branch the hardware target relaxes: eval sweeps run single-GPU (or even CPU for short articles), don't need RCP, and don't need the production container.

## Testing

Unit tests land **in the same change as the code they cover**, not as follow-up. Layout is flat `tests/test_<module>.py` against `src/impresso_text_embedder/<module>.py` — most modules already have a peer; new modules should add one. Framework is `pytest` (configured in `pyproject.toml`, `-ra --strict-markers`), runnable on a CPU-only Mac because CUDA is mocked at the call sites that need it (see `tests/test_model.py`, `tests/test_accel.py`) and `conftest.py` stubs the `/rcp-scratch` PVC to a tmp dir.

Functional/GPU-correctness tests (real model load, real S3, real encode) are **out of scope for local dev** — they run on RCP against the container image. Don't gate local work on them, and don't add `skipif(not torch.cuda.is_available())` — mock the CUDA surface instead so the test runs everywhere.

For research code on this branch: same rule. Eval-harness modules get peer test files. Notebooks are fine as supplementary artefacts but the core logic stays importable and unit-tested.

## S3 layout

Input (one bucket, one file per newspaper-year):

```
s3://<input-bucket>/<provider>/<alias>/<alias>-<year>.jsonl.bz2
```

Output (mirrored 1:1):

```
s3://<output-bucket>/embeddings/docs/<model-slug>/<provider>/<alias>/<alias>-<year>.jsonl.bz2
```

- `<model-slug>` follows the Impresso versioned-embedding convention. `Alibaba-NLP/gte-multilingual-base` → `embeddings_gte_v1-1-0` via `pipeline.MODEL_SLUG_OVERRIDES`. Unknown models fall back to stripping the HF vendor prefix. Revision is **not** appended to the slug — different revisions of the same model share the output path.
- 1 input file → 1 output file, same basename. No sharding, no merging.
- Provider/alias/year combinations vary in size; do not assume uniform shape.

Credentials live in `.env` at the repo root. **Never read the contents of `.env`.** Variable names: `SE_ACCESS_KEY`, `SE_SECRET_KEY`, `SE_HOST_URL`.

Research-side input sampling reads the same buckets through the same `s3io` helpers. Research outputs (eval datasets, per-strategy embedding caches, Chroma-style query/excerpt JSONs) live under `tmp/` or `.out/` locally — they do **not** write to the production output prefix.

## Data contract

Schemas come from `git show main:lib/text_embedding_processor.py` — read it for full detail.

### Input record (one per line in the input `.jsonl.bz2`)

- `id` — canonical content-item id (string).
- `tp` — content type. Filter to `ar` (articles) by default; `--content-type page` allows pages.
- `lg` — language code (optional).
- `sents` — list of sentence dicts. Each has `tok: [{t: <token>, o: <char-offset>}, …]` and an optional sentence-level `o`.
- `ft` may be absent; reconstruct via `text.rebuild_ft_from_offsets` (offsets absolute, gaps padded with spaces). Preserve that helper's exact behaviour.
- `lingproc_path` — optional provenance, echoed through to the output when present.

### Output records (one line per content item)

Shape depends on `--embedding-level`:

- **text** (default, one embedding per document) — the authoritative Impresso document-embeddings schema (`embeddings-docs.schema.json`): required `{ci_id, model_id, embedding, size}`; optional `{ts, ci_type}`.
- **sentence**: `{ts, ci_id, sents: [{sent_id, embedding, size, lg?, o?}, …], model_id?, lingproc_path?, git?}`.
- **chunk**: `{ts, ci_id, chunks: [{chunk_id, embedding, size, lg?, o?}, …], model_id?, lingproc_path?, git?}`.

Embeddings are stored as a list of floats rounded to 5 decimals. `ts` is UTC `YYYY-MM-DDTHH:MM:SSZ`. The text-level schema is verified against the authoritative spec; sentence- and chunk-level schemas are not yet.

### Chunking & aggregation registries

Two orthogonal kwargs-capable registries handle the >8192-token case: `impresso_text_embedder.chunking` (text → K chunk strings) and `impresso_text_embedder.aggregation` (K chunk vectors → 1 doc vector). Defaults and the boundary rule are pinned in [Decisions inherited from the migration](#decisions-inherited-from-the-migration) → "Long-doc handling". Full design space in `.history/long-doc-chunking/notes.md`; registry contract in `.history/chunking/notes.md`. **The chunking-eval research on this branch operates within these registries — new strategies land as a new module + one `register_strategy` line, not as parallel infrastructure.**

## Non-goals

- Multi-node, DDP, FSDP, tensor-parallel — all forms of model-parallel inference. (Horizontal throughput via **file-level data parallelism** — one container per shard, one GPU per container, model replicated across containers — is the chosen pattern; see [`.history/multi-gpu-sharding/notes.md`](./.history/multi-gpu-sharding/notes.md).)
- Non-Ampere/Hopper GPU variants (V100, Blackwell) — deferred.
- Incremental/partial-file recovery mid-shard. A file either completes or is redone.
- Local-only workflows beyond tests — production flow is S3 in, S3 out.
- A new Make-driven data pipeline. The existing `Makefile` only wraps `docker buildx`, `kubectl`, and `runai submit` — no data flows through it.
- Production-pipeline changes from the chunking-eval branch until findings justify a default change.

## Decisions inherited from the migration

These were locked during the 18-step migration that lives in [`.history/plan.md`](./.history/plan.md). They are **invariants** for chunking-eval research — don't relitigate them without explicit user sign-off. Each entry's deep rationale lives in the linked notes file under `.history/`.

- **Validation metric:** cosine distance on L2-normalized vectors; default tolerance `1e-4`. Rationale in `.history/validation-metric/notes.md`.
- **Model slug:** Impresso versioned-embedding convention — `Alibaba-NLP/gte-multilingual-base → embeddings_gte_v1-1-0` via `pipeline.MODEL_SLUG_OVERRIDES`. Unknown models fall back to stripping the HF vendor prefix. Revision is **not** appended to the slug; different revisions of the same model go to the same output path. When a new Impresso-blessed model is added, register its slug in the override map.
- **JSON codec:** `orjson` on both read and write paths (`orjson.loads` on input lines, `orjson.dumps(..., option=OPT_APPEND_NEWLINE)` on output). Output bz2 file is opened in binary mode (`bz2.open(path, "wb")`) since orjson returns bytes. Embeddings rounded to 5 decimals on write (handled by `schema.to_dict`). Rationale in `.history/io-throughput/notes.md`.
- **Per-provider pipeline overlap:** `process_provider` drives two single-slot `ThreadPoolExecutor`s — one prefetcher downloading file N+1 while file N encodes, and one uploader sending file N's output while file N+1 encodes. Backpressure is implicit (wait on the previous upload future before submitting the next). Inputs are fetched with `boto3.s3.transfer.TransferConfig(multipart_threshold=8 MB, multipart_chunksize=8 MB, max_concurrency=10, use_threads=True)`; this hits Ceph RadosGW (Switch Engines) with parallel ranged GETs. Rationale in `.history/io-throughput/notes.md`.
- **Per-file telemetry:** `telemetry.StageTimer` + `telemetry.GpuSampler` emit one INFO line per completed file with `download_s`, `encode_s`, `upload_wait_s` and `gpu_util_mean`/`p10`. `GpuSampler` soft-imports `pynvml` (bundled by NGC) and no-ops cleanly when it's missing. Rationale in `.history/io-throughput/notes.md`.
- **Streaming inputs:** hand-rolled (see `.history/io-layer/notes.md`); `impresso_essentials.io.s3.read_jsonlines` is intentionally unused on the hot path.
- **A100 bf16 strategy:** autocast around `encode()`, model weights stay fp32. Recorded in `.history/gpu-throughput/notes.md`. Revisited in `.history/gpu-profiles/notes.md` (Q2): stays the recipe on H100 too — xformers dispatches on Q/K/V dtype, which is bf16 inside the autocast region regardless of weight dtype. Overridable via `--precision {bf16,fp32}` on `impresso-embed-create` for ablation against an older fp32 baseline; default unchanged.
- **GPU profile detection:** `accel.py` reads `torch.cuda.get_device_capability()` at model-load time and returns a profile with the default batch size. cc `(8,0)`→A100=64, cc `(9,0)`→H100/H200=128, others→32 with a warning, CPU→8. Runtime detection (not build-time) so one image runs on either arch and the startup log records what landed. Rationale in `.history/gpu-profiles/notes.md`.
- **xformers + unpadding wired as the default fast path:** when xformers is importable and the device is CUDA, we pass `config_kwargs={"unpad_inputs": True, "use_memory_efficient_attention": True}` to `SentenceTransformer` — not `model_kwargs`. Each flag is independently overridable via `--attention {xformers,eager}` and `--unpad-inputs / --no-unpad-inputs` on `impresso-embed-create` for drift bisection; with `--attention=xformers` we now fail loud at load time if xformers isn't importable or the device is CPU, instead of silently falling back. Defaults preserve the historical fast path. Alibaba's custom modeling file reads these off `self.config`, and sentence-transformers v5 pre-loads the config and passes it explicitly to `from_pretrained`, which makes HF skip the kwarg-to-config routing that `model_kwargs` would have relied on; forwarding through `config_kwargs` lands them on the config object via `AutoConfig.from_pretrained(..., **config_kwargs)`. The modeling file then routes through `xformers.ops.memory_efficient_attention`. HF-generic `attn_implementation` does **not** work for this model (the custom modeling file rejects it with `NewModel does not support Flash Attention 2.0 yet`). NGC 25.03 does not bundle xformers, so the Dockerfile pins `xformers==0.0.30` from PyTorch's cu128 wheel index with `--no-deps`. xformers dispatches to FA2/FA3 only when `flash-attn` is also installed; today we install xformers alone (CUTLASS kernel — still a real speedup with unpadding), with `flash-attn` deferred as a measurable lever. Full research in `.history/gpu-profiles/notes.md`.
- **Re-embed on input change:** compare S3 `LastModified` of input vs existing output at skip-decision time. Input timestamps come from `list_objects_v2` (no extra HEAD), output via `head_last_modified`. `--force` overrides unconditionally. Known gap: byte-identical re-uploads still trigger a re-embed, and this does not replace the deferred `impresso-essentials.versioning` manifest. Rationale in `.history/reembed-on-change/notes.md`.
- **impresso-essentials vendored, not imported:** the package is **not** in `pyproject.toml` and not installed in the Docker image. Its 1.4.x metadata hard-pins `numpy==2.2.1` (plus dask, pandas, pyarrow…), which would uninstall NGC's `numpy==1.26.4` and break the apex/NCCL/transformer-engine/xformers ABI stack. A `--no-deps` install also fails because `impresso_essentials.io.s3` does `import dask.bag as db` at module level. The three helpers we used (`get_s3_client`, `get_s3_resource`, `upload_to_s3`) are vendored into `src/impresso_text_embedder/io.py` — ~40 lines of boto3 wrappers reading `SE_*` env vars. Full rationale in step 12 of `.history/plan.md` and `.history/io-layer/notes.md`.
- **Text-level output schema aligned with Impresso document-embeddings schema:** required `{ci_id, model_id, embedding, size}`, optional `{ts, ci_type}`. Previously wrote `{id, ts, embedder, len, embedding, text?}` — all four divergences fixed (renames + drops + added `size`). `--include-text` CLI flag removed with the field. The `model_id` *value* still carries the `name@revision` tag from `build_embedder_tag`; aligning that string with the Impresso slides convention (e.g. `doc-embeddings_<slug>-vX-Y-Z`) is a deferred follow-up. Rationale in `.history/create-cli/notes.md`.
- **Upload integrity:** disable boto3's default flex-checksums with `Config(request_checksum_calculation="when_required", response_checksum_validation="when_required")` — the `when_supported` default makes `PutObject` send `aws-chunked` with no `Content-Length`, which Ceph RadosGW (Switch Engines) rejects with `MissingContentLength`. Needs `boto3>=1.36.5` (pin bumped) so the setting propagates through the TransferManager used by `upload_file`. Each upload is then verified by streaming a local MD5, HEAD-ing the uploaded object, and checking `ContentLength` against local size plus (single-part only) ETag against MD5; multipart ETag reconstruction is deferred. On mismatch the bad object is best-effort-deleted so `--skip-if-s3-exists` doesn't hide the failure. Rationale in `.history/upload-integrity/notes.md`.
- **Transformers pinned `<5`:** `transformers>=5` corrupts `position_ids` on `Alibaba-NLP/new-impl` (the `trust_remote_code` modeling repo behind `gte-multilingual-base`) because v5's meta-device loading skips re-initialising `persistent=False` buffers, and Alibaba registers `position_ids` that way. The crash surfaces as a CUDA IndexKernel assert at `modeling.py:392 rope_cos[position_ids]` on **any** input — including the Makefile's 6-token smoke test — so it is not a sequence-length bug. Pinned `transformers>=4.46,<5` and `sentence-transformers>=3.0,<5.2` in `pyproject.toml`, re-asserted in the Dockerfile as `transformers>=4.46,<5` + `sentence-transformers>=5.0,<5.2` + a build-time `assert transformers.__version__.startswith('4.')` guardrail. Upstream trackers: HF transformers #43950, #44534; model discussion #30. `Alibaba-NLP/new-impl` is unmaintained (last commit Aug 2024), so the fix lives on our side until we either see an upstream v5 fix or switch embedder. Full rationale — including the red herrings we ruled out (sequence length, xformers unpad path, BL-specific content, NGC image mismatch) — in `.history/transformers-v5-regression/notes.md`.
- **Model revision pinned to `f7d567e`:** `Alibaba-NLP/gte-multilingual-base` is loaded at a specific HF commit so upstream re-tags can't silently change the weights and invalidate the `--tol 1e-4` cosine validation contract. Single source of truth: `DEFAULT_MODEL_REVISION` in `src/impresso_text_embedder/model.py`; `load_model` and the `--model-revision` CLI default both read it. The `Makefile` mirrors the pin as `CREATOR_NAME`/`HF_MODEL_NAME`/`HF_MODEL_VERSION` (`?=` so `.env.docker` overrides win) and `runai-submit` forwards them as explicit `--model-name` + `--model-revision`, which makes the pin recoverable from `runai describe job` even if the image changes. Output slug stays revision-agnostic (`embeddings_gte_v1-1-0`) — the pin is about reproducibility, not about forking output paths. Rationale, bump workflow (one-off in `.env.docker` vs permanent in `model.py`), and deferred `huggingface_hub` SHA-verify follow-up in `.history/model-revision-pin/notes.md`.
- **Structured logging split file ↔ terminal:** `impresso-embed-create` writes a full INFO log to `/rcp-scratch/<username>/experiments/embeddings/<YYYY-MM-DD>/<provider>.log` (override with `--log-dir <path>`; file level via `--log-level-file`, default `INFO`). The terminal shows a single `tqdm` bar over the planned files with per-file `set_postfix(dl=…s enc=…s up=…s gpu=…%)` from `StageTimer`/`GpuSampler`; only `ERROR` records reach the terminal, via a `TqdmLoggingHandler` that calls `tqdm.write` so stack traces don't shred the bar. If `/rcp-scratch` is not mounted and no `--log-dir` is given, the CLI exits non-zero with a clear "PVC not mounted" message — no silent fallback (dev fallback to `./logs/` was rejected because it would mask a PVC misconfig on RCP). Username via `getpass.getuser()`, which matches `LDAP_USERNAME` inside the container. Scope: `impresso-embed-create` only; `impresso-embed-validate` is a one-shot diagnostic and keeps its old stderr logging. Full rationale, rejected alternatives (per-run timestamped dirs, structured JSON logs, rotating file handler), and the tqdm-postfix format choice in `.history/structured-logging/notes.md`.
- **Record filtering — `missing_content_type` distinct from `content_type`:** records with `tp not in cfg.content_types` and records with `tp` absent are tallied under separate reasons. Missing `tp` is anomalous enough to deserve a one-shot WARNING per file (first occurrence only; later ones DEBUG) so data-quality drift surfaces without spamming the log. The existing `telemetry.format_stats_line` surfaces both counts in the per-file `done` line (`skipped=N (content_type=X missing_content_type=Y …)`). Restores parity with legacy `a433970:lib/text_embedding_processor.py:257-259`, which dropped `None not in ["ar"]` → True under `skipped_type_None`; the migration's `_passes_content_type` had loosened this to pass missing `tp` through. Rationale, drift-from-legacy table for every filter reason, and rejected alternatives (per-record WARN, summary-only WARN, CLI escape hatch) in `.history/record-filtering/notes.md`.
- **Validate — source-backed diagnostics (drifted + missing) + Rich rendering:** `impresso-embed-validate --source <path>` (local or `s3://`) cross-references the ids that land in the three mismatch buckets — `above tolerance` (`MismatchKind.VALUE`), `missing in target`, `missing in produced` — against the original input shard and emits a per-direction diagnostic panel with `{total, found_in_source, not_in_source, reconstructable, empty, below_min_char_<N>}` counts, a char-length log-scale histogram + percentiles, `lg` / `tp` breakdowns (with a `(missing)` bucket for absent fields), and sample excerpts. Source text is reconstructed via `ft` if present, else `text.rebuild_ft_from_offsets(sents)`, else empty. The `above tolerance` panel renders first with `border_style="red"`; its 3 samples are the **worst drifts** by record-level max cosine distance across item-level mismatches, each annotated `d=<distance>`. The two missing panels render below with `border_style="yellow"`; their samples are the first 3 encountered (distance is `None` by construction). Samples are surfaced via a `Sample(ci_id, excerpt, distance | None)` dataclass hanging off `ValidationReport.source_stats`. The CLI renders via `rich.console.Console(force_terminal=None)` so ANSI is auto-stripped when stdout isn't a TTY — pytest's `capsys` and CI log pipes keep the same plain-text stream they had before, and every legacy substring contract from step 7 (`records_checked=`, `MISMATCH:`, `p50=`, `log10(distance)`, `worst drifts`, `mismatches`, `missing in target (N)`, `OK`, `FAIL`) is preserved as plain `console.print` lines outside the Rich tables. Reverses the step-7 decision to stay plain text, since the renderer needed structured rendering anyway for the new panels and a no-color Rich console is strictly better than the old string-concatenation path. `ValidationReport.source_stats` is an optional diagnostic field; `passed` is untouched (a mismatched record is still a fail regardless of its source-text characteristics). `--source` without `--target` emits one `WARNING` on stderr and is otherwise ignored. Rejected alternatives (tokenizer-based length, JSON sidecar, replaying the full create-CLI filter predicate, separate `impresso-embed-explain` CLI, a separate `DriftStatsBlock` type, folding above-tol samples into the existing `worst drifts` table) and open items (per-`lg`/`tp` mean-drift tables inside the VALUE panel, drift-vs-length correlation, `--source-samples N` knob, histogram edges, auto-derive `--source-min-char-length` from the create-run log) in `.history/validate-source-stats/notes.md`.
- **`--normalize-embeddings` removed; encoder must ship `Normalize` module:** the CLI flag and `EncoderConfig.normalize_embeddings` field were deleted. They were a no-op on `gte-multilingual-base` (which ends with a `2_Normalize` module that already produces unit vectors) and the two defaults disagreed (CLI `False`, EncoderConfig `True`) — silently invisible on this model, a foot-gun on any other. `model.encode(...)` is now called with `normalize_embeddings=False` (we trust the built-in module), and `load_model` asserts the last `SentenceTransformer` module is `sentence_transformers.models.Normalize`, raising `RuntimeError` with `name@revision` otherwise. The cosine validation contract (`--tol 1e-4`) is now a load-time invariant. `MeanPoolStrategy`'s post-mean L2 renorm is unaffected — it operates on a different vector (the aggregated mean) and remains required for unit-norm document outputs. If a future encoder swap drops the `Normalize` module the assertion fires; the fix is to add an explicit normalisation step inside the aggregator (or per-aggregator contract), not to re-add the flag. Rationale and rejected alternatives (auto-detect from `modules.json`) in `.history/normalize-flag-removal/notes.md`.
- **Multi-GPU throughput via file-level sharding:** horizontal scaling lives in the orchestration layer, not in the container. `impresso-embed-create --shard-index i --num-shards N` selects a disjoint partition of `s3io.list_input_keys` via round-robin (`enumerate(keys) % N == i`), applied lazily as a filter at `pipeline._plan_files`. `list_objects_v2` returns UTF-8 lexicographic order on both AWS S3 and Ceph RadosGW, so the partition is deterministic without an explicit sort. One runai job per shard, one GPU per job, model replicated across jobs — no DDP, no NCCL, no shared queue, no leader election. Re-runs are idempotent via the existing `--skip-if-s3-exists` + `reembed-on-change` `LastModified` check; a failed shard re-runs by re-submitting the same `(i, N)`. Defaults `--shard-index 0 --num-shards 1` reproduce single-job behaviour. Both flags or neither — error at parse time if exactly one is non-default. Per-shard log filename becomes `<provider>-shard-<i>-of-<N>.log`. Round-robin chosen over contiguous-range (sorts skew across shards), stable hash-mod (no payoff when N is fixed), size-aware greedy (deferred — file size ≠ encode time; promote only if measured shard wallclock skew >2×), and consistent hashing (overkill — no elastic resharding). The `--shard-index` / `--num-shards` flag-pair contract matches pytest-shard and HuggingFace `datasets.shard(num_shards, index, contiguous=False)`. Makefile gains `runai-submit-shard` (single shard) + `runai-submit-multi NUM_SHARDS=N` (loop). - **Study-config YAML — single source of truth for chunking-eval research parameters:** every research-pipeline parameter (corpus filter, chunk grid, query budget, model pin, S3 paths) lives in one YAML per *study* under `configs/research/`, loaded via the Pydantic schema in `src/impresso_text_embedder/research/study_config.py`. Layout: `base.yaml` holds cross-study invariants (model pin, providers, year window, query-generation defaults); each study YAML declares `extends: base.yaml` and overrides only the fields that differentiate it. Loader does single-level deep-merge (no chained `extends:`), validates `extra="forbid"` to catch YAML typos, and enforces cross-field invariants (`max_tokens > min_tokens`, every language has a `providers` and `chars_per_token` entry, `year_min ≤ year_max`, every `paths.*` template contains the `{study}` placeholder). `StudyConfig.resolve_path("corpus_s3_key")` substitutes `study.name` at access time so two studies cannot share an S3 key. `StudyConfig.config_sha` is a stable 12-char SHA256 fingerprint of the merged config; embedded in every output record alongside `study_name` so two runs of the same study with different YAML edits are distinguishable in S3. The four research CLIs (`corpus_select`, `corpus_fetch`, `embed_sweep`, `query_generate`) take `--config <path>`; per-flag CLI args remain as one-shot overrides (e.g. `--limit 10`). Scenarios are no longer a hardcoded tuple in `scenarios.py` — `scenario_builder.build_scenarios(cfg.scenarios)` expands `{truncate_baseline} ∪ (chunkers × chunk_sizes)` into auto-numbered `S0..SN`, validated against the live chunking + aggregation registries. `Makefile` is driven by `STUDY ?= study-v1`; `SCENARIOS` shells out to `python -m research.scenario_builder --config $(STUDY_CONFIG) --list-ids`. Operational knobs (`--limit`, `--no-upload`, `--max-workers`, `--batch-size`, `--log-dir`) stay on the CLI, not in YAML — research parameters describe *what* the experiment is, CLI flags describe *how to run it this time*. Rationale, rejected alternatives (single multi-study YAML, TOML, Hydra, chained `extends:`, globally unique scenario ids `A-S0..B-S15`, auto-derived chunkers), and follow-up step 6 (run study-A-fit and study-B-overflow against the refactored pipeline) in `.progress/study-config/notes.md`.
- **Long-doc handling at `--embedding-level text` — partial landing, extensible by design:** architecture is two orthogonal registries — `impresso_text_embedder.chunking` (token-aware chunkers) and `impresso_text_embedder.aggregation` (chunk-vector → doc-vector). Both registries accept kwargs so future strategies inject runtime deps (tokenizer, decay coefficient, …) without CLI-surface churn. Today the CLI wires `chunking="fixed-window"` (dumbest-thing-that-works: tokenize → slice into contiguous non-overlapping windows of `tokenizer.model_max_length - num_special_tokens_to_add(pair=False)` ids → decode; no sentence regex, no overlap, no chonkie) + `aggregation="mean"` (mean pool + L2 renorm). `chunking="token-budget"` (sentence-aware greedy packer) is also registered but opt-in — reachable via `get_strategy("token-budget", …)` for A/B testing once `fixed-window` has a baseline. Additional strategies land as a new module + one `register_strategy` line + one `choices=` tuple entry. Wiring: `EncoderConfig.long_doc: LongDocConfig | None` (default `None` = legacy behaviour); when active, `TextBatcher` detects long docs via a cheap chars-per-token pre-filter then a real tokenise, chunks via the registered chunker, rides the K chunk texts on the same batched `encode_texts` call as short docs, and aggregates K→1 vectors per-record on flush. CLI flags: `--long-doc-strategy {truncate,chunk}` (default **`chunk`** — long docs no longer silently truncated; `truncate` is the opt-out for reproducing pre-chunking outputs), `--long-doc-chunk-tokens N` (default **`None`** — auto-derived at CLI-init time from the loaded model's tokenizer as `model_max_length - num_special_tokens_to_add(pair=False)`; 8190 for gte-multilingual-base; `_FALLBACK_CHUNK_TOKENS=8000` used only if the tokenizer doesn't advertise the attrs), `--long-doc-aggregation {mean}` (only choice today). **Boundary decision (the question this branch revisits empirically)**: chunking only fires when `tokens(doc) > model_max_tokens`; for docs ≤8192 the one-shot path wins on theoretical grounds — `gte-multilingual-base` uses CLS pooling (confirmed via `1_Pooling/config.json`) and is natively trained at 8192 with RoPE, so chunk-and-pool strictly drops cross-chunk attention without a mechanism to recover it, and Jina's own "No Chunking" benchmark beats both naive and late chunking on NFCorpus. **Two independent L2 normalizations, not one.** The encoder applies per-chunk L2 normalization via the model's built-in `2_Normalize` module — `load_model` asserts its presence at startup and refuses to run otherwise. MeanPoolStrategy applies a second L2 renormalization on the *aggregated* mean vector — because the mean of K unit vectors is not itself unit-norm. Different inputs, different necessity, different pipeline stages; do not fold one into the other. Full analysis in the "Two independent L2 normalizations" section of `.history/long-doc-chunking/notes.md`. Late Chunking (Jina 2024) **rejected** for this embedder: it assumes a mean-pooled model, and applying it to a CLS-pooled one puts the output in a subspace the training loss didn't shape; reconsider only if we switch embedders. Full design space (11 chunking options A–K, 8 aggregation options α–θ, literature anchors, CLS-pooling deep-dive, shipped/deferred split) in `.history/long-doc-chunking/notes.md`.
